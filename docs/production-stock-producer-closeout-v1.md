# Production stock producer reconciliation

The production database had all five read authorities but none of their producer RPCs. The bounded installation restores the CURRENT LIVE lease/receipt functions and the stock job/observation repository functions without replaying historical migrations. See [the exact attestation](production-stock-producer-attestation-v1.json) for objects, source migrations and deferred dependencies.

The existing monitor intake now has an explicit production workload-authenticated branch. It admits no caller account, token, target, item, URL or body and returns before the existing PREPROD marketplace writers. It uses the existing canonical configuration getter, official LIVE reader, cohort certification, lease, retry window and stock producer. The GET stockguard-read route and its authentication/grants remain unchanged. No scheduler, worker or heartbeat is added. A bootstrap invokes this same normal entry once; it is not a seed.

The source binding is checked inside the production runtime before any lease or official eBay call. Configured orders access is not evidence that the full LIVE source adapter has a usable account-bound grant. Missing source configuration stops with its exact key names, never values. Dependency metadata subsequently stops before linkage/stock if the required resolver or its source objects are absent.

CURRENT LIVE success atomically persists the complete cohort plus source receipt; identical replay is a no-op and conflicting receipt/lease is rejected. Failure preserves last known scope and backoff. Stock job creation requires CURRENT LIVE plus latest exact approved linkage. Observation persistence verifies the exact product/variant/SKU component, owned lease, attempt, source semantics and evidence. Completion requires a receipt for every certified component. Supplier quantity remains nullable; UNKNOWN/unavailable never becomes zero or OUT_OF_STOCK.

The old relist resolver cannot be installed on this schema independently: it compiles against package/opportunity row types and consumes certified lineage and supplier catalog authorities missing in production. Its historical migration also changes publication completion. Creating empty source tables, copying PREPROD rows or guessing identity from title would not close that gap. No such operation is performed. The deferred exact dependency is reported separately from the safely installable producer subset.

Validation executes the actual SQL in PostgreSQL-compatible PGlite from the old reconciled production schema, repeats installation, preserves legacy rows and table security, exercises current-cohort receipt replay/failure, stock component receipts, wrong account, availability-only and unknown states. Runtime tests enforce absence of side effects when dependencies are missing. Production population and physical stock PASS remain false until the production runtime produces and reads back real CURRENT authorities.
