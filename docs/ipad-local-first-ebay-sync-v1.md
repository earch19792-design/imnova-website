# SELLER_OS_IPAD_LOCAL_FIRST_EBAY_SYNC_V1

Mayel autosaves the operator's workspace and generated draft intents to IndexedDB, then immediately attempts a durable, authenticated Seller OS handoff. eBay availability is not consulted during either save. The existing scheduled operational-integrity runtime processes the durable queue; Safari does not need to stay open after a server receipt.

The workspace retains menu, selected listings and page, metric period, policy and schedule. Drafts retain identity, generation, requested changes, creation time, base evidence and a stable actor-scoped idempotency key. Saved image references point to the existing private backend asset; no new generation or manual upload is needed. The local storage module also supports a bounded image Blob store. Outbox records exclude credentials, sessions, request headers and signed URLs; existing application authentication storage is separate from this feature.

Save status uses GUARDADO, PENDIENTE_DE_SINCRONIZAR, SINCRONIZADO and REQUIERE_ATENCION. Technical receipt and failure information is under Ver detalles. Reopening Mayel, returning to its tab or recovering connectivity triggers handoff automatically. A storage failure is shown as attention, never as a successful save. Cold starting the complete application with no Seller OS connection is not an offline PWA guarantee.

The server validates actor/account/listing/origin independently of the browser and returns the same receipt for the same intent, including after a lost response. Database leases use SKIP LOCKED; immutable identity and payload checks prevent key reuse with different changes. An unknown commit is persisted before external dispatch. Recovery reads official eBay evidence before any further action; an unresolved commit requires attention. A single runtime run dispatches at most one new outbox operation, including when its outcome is unknown.

Only image operations backed by an approved current Mayel manifest and human product QA can execute. The outbox retains the original ordered-image digest and stored official title, SKU, price, currency and quantity. Current official readback, matching bases, active identity, approved asset, visual-only diff and existing executor safety checks precede dispatch. Different or unavailable bases require attention; no silent rebase occurs. The existing executor independently claims one write and verifies all protected fields and the ordered images through official readback. Legacy runtime discovery excludes outbox-bound tasks, so it cannot bypass the outbox's version or unknown-commit hold.

Saved visual proposals remain private until the operator completes the displayed comparison checkbox and explicitly presses **Confirmar y enviar cuando eBay esté disponible**. This grants initial image queue authority; no additional resume button is needed after authorization. The 366582671136 canary must stop before that control, retaining the user's no-publish/no-eBay-write constraint. Its DRAFT_ONLY execution and manifest are separate from a marketplace execution receipt.

Ads policies and listing previews are durable drafts. They do not authorize marketplace writes. Ads execution remains disabled and no Ads executor is introduced by this change. Any future Ads activation still requires the existing Fee Authority, fresh shipping/cost evidence, recomputed profit/margin/safe rate, certified official Ads contract, enabled Ads flag and OWNER spending authorization. An old policy cannot become spend authorization. Unknown costs remain unknown. Multi-listing Ads writes remain disabled.

Preprod migrations add the server-only outbox and permit the exact saved generator origin to enter an unlinked visual task. The latter fixes the 1136 asset admission failure: the account-scope trigger previously required a Listing Package even for a valid private visual draft. Account, task, assignee, source hash, durable experiment and QA provenance must match; ordinary publication guards remain in force. A resumed prepare keeps its original execution identifier.

Validation: targeted domain and PostgreSQL tests exercise quota retention/resume, stale bases, concurrency, lost-response idempotency, unknown commits, account isolation, immutable records, RLS and no spending from drafts. Browser and complete-suite results are recorded in the accompanying closeout evidence after execution. Tests using injected upstream adapters prove control flow without spending or writing to eBay; they are not a physical post-quota eBay certification.

IndexedDB writes resolve on transaction completion, following [MDN's transaction completion contract](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction/complete_event). The outbox table intentionally has RLS enabled and no user policies; only the service role has table/RPC privileges, following [Supabase's server-side RLS guidance](https://supabase.com/docs/guides/database/postgres/row-level-security).
