# Seller OS Experience 2026-2030 - auditoría de fundaciones

## Resumen ejecutivo

La experiencia anterior no tenía un shell administrativo persistente. Cinco destinos se definían en un archivo común, pero cada página decidía si renderizarlos y cuál estaba activo. El resultado era navegación duplicada, nombres distintos, rutas profundas sin breadcrumbs y estados escritos manualmente que podían contradecir la ejecución durable.

La Fase 1 introduce un shell único para Preview, cinco áreas orientadas al trabajo y una navegación utilitaria. No cambia máquinas de estado, APIs, base de datos, publicación ni autorizaciones.

`app/admin/sidebar.tsx` continúa como componente huérfano y no se elimina en esta fase. Las pantallas técnicas siguen accesibles mediante rutas compatibles mientras sus funciones se migren gradualmente.

## Matriz de configuración

| Configuración | Clasificación | Fuente | Consumidor | Tratamiento UX |
| --- | --- | --- | --- | --- |
| `SELLER_OS_UX_V2_ENABLED` | Activa, no secreta | Vercel Preview | `app/admin/layout.tsx` | Permite desactivar el shell en Preview |
| `VERCEL_ENV` | Activa, técnica | Vercel | `app/admin/layout.tsx` | Impide habilitación automática en Production |
| Controles de publicación eBay | Sensibles | Control plane existente | Servicios Seller OS | No se muestran como activos/apagados sin lectura runtime |
| Configuración OpenAI | Sensible | Gateway existente | Casos de uso registrados | No se infiere desde texto estático |
| Digest comercial | Activa | `commercial_intelligence_configs` | Monitor comercial | Se presenta desde la fuente, sin hora hardcodeada |
| Estados comerciales legacy | Pendiente de migración | `product_states` | Dominio Productos legacy | No conectado a Seller OS |

## Problemas confirmados y resolución

| Problema | Evidencia | Resolución Fase 1 |
| --- | --- | --- |
| Navegación por pantalla | `SellerOsMobileNav` en varias páginas | Shell y navegación canónica |
| Salud y Operación comparten ruta | Anchors `#operacion` y `#salud` | Área Operación + utilidad Configuración |
| Estados estáticos | OpenAI, Production, hora y piloto en copy | Retirados o reemplazados por disponibilidad runtime |
| Animación temporal | Timers en Listing Workspace | Sólo existe movimiento durante efecto in-flight real |
| `null` mostrado como cero | Conversión con `Number(null)` | Parser nullable explícito |
| Datos agregados incompletos | Endpoint sin heartbeat o producto activo | “No disponible”; nunca “Trabajando” |

## Arquitectura de navegación

1. Inicio: `/admin`
2. Oportunidades: `/admin/ebay/mobile-review`
3. Productos: `/admin/ebay/listing-workspace`
4. Operación: `/admin/ebay-seller-os#operacion`
5. Monitoreo: `/admin/ebay/seller-performance`

Decisiones, Alertas, Cuarentena y Configuración viven en navegación utilitaria. `/admin/products` no se habilita hasta implementar la Fase 2 y validar el aislamiento del dominio legacy.

## Contrato de estados y movimiento

Sólo `WORKING` puede animarse y requiere simultáneamente estado durable, heartbeat reciente, lease vigente, pestaña visible y movimiento permitido. Un estado activo sin esas pruebas se presenta como `En cola`. `null`, campo ausente, error, dato parcial y cero confirmado son estados diferentes.

## Dependencias y riesgos

- El endpoint agregado no expone heartbeat, lease, producto activo, fase ni decisiones humanas.
- No existe herramienta browser E2E o axe instalada; incorporarla requiere aprobación separada.
- Las páginas monolíticas conservan navegación de compatibilidad que ya no genera DOM.
- La lista y detalle `/admin/products` continúan fuera de alcance hasta la Fase 2.
